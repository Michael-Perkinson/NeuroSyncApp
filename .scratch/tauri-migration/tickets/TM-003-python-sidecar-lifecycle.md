# TM-003 - Python sidecar process lifecycle

**Priority:** P0 (foundation)
**Depends on:** TM-001
**Blocks:** TM-020, TM-023, TM-024, TM-025
**Status:** proposed

## Context / evidence

The backend must be a local process the frontend can talk to. The current app
runs everything in one process with a coarse error boundary at startup
(`main.py:20-36`). Thread/worker lifecycle patterns to model shutdown after:
the raw-photometry widget owns a `QThread` per job and cleans up on close with a
3-second wait then a "Still working" modal (`photometry_processing_widget.py:620-667`,
`811-826`).

Today the app is single-instance and fully offline; there is no daemon
lifecycle, health check, or crash recovery.

## Required work

1. Spawn the sidecar from the Tauri Rust host at app start: locate the bundled
   binary (dev vs release path), set env, redirect stdout/stderr to a log.
2. Auth handshake: per-launch token generated by the host, passed via env or
   handshake line before any request is accepted (see TM-020).
3. Health: `ping` with timeout and retry; if the sidecar dies, surface a
   recoverable error in the UI and offer restart.
4. Graceful shutdown: `shutdown` request, then force-kill with timeout; ensure
   no orphan processes on app quit (also on webview crash / window close).
5. Single-instance guard (the PySide6 app has none; confirm desired behavior).
6. Deterministic logging: sidecar writes a log file next to the config dir for
   support (mirrors today's console logging in `main.py:10-18`).

## Acceptance criteria

- [ ] Sidecar starts, authenticates, and answers `ping`.
- [ ] Killing the sidecar process is detected and the UI offers recovery
      without losing the in-memory analysis.
- [ ] Quitting the app leaves no orphaned Python process on Windows or macOS.
- [ ] Sidecar crash/exit is logged with enough context to debug.

## Risk

- Process/pipe teardown races on macOS (WKWebView teardown ordering) and
  Windows (console vs windowed process).
- Startup latency of a numpy/pandas/scipy sidecar on cold start.

## Validation strategy

- Integration test driving the real binary: spawn, ping, kill -9, restart,
  shutdown, check for orphans (via process list on each OS).
- Manual smoke on all three targets.
