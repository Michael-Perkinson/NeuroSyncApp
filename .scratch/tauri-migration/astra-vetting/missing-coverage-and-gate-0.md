## Concrete Gate 0 cut

**Goal:** decide whether the selected desktop/sidecar architecture can ship on all three targets and support a deep scientific workflow interface. Gate 0 does not claim full feature parity or retire anything.

Use these defaults for the bounded experiment: stdio with Rust owning the child; one session and one job at a time; no background-on-close mode; explicit cancelled/lost-session statuses; manual downloads; Combine remains unavailable; existing settings path/key formats are preserved. Use co-bundled version negotiation. These are proposed implementation defaults, not approvals to change current production behaviour.

Do not make Gate 0 depend on every future operation or a universal chart schema. The following six deliverables are sufficient, provided each has actual evidence:

| Step | Bounded scope | Required proof |
| --- | --- | --- |
| G0-A baseline packet | Choose one small single-channel raw fixture and one small behaviour recording/coding pair; include a deterministic generated dual-panel/telemetry-like plot fixture. Capture current outputs and relevant artist/table observations with exact versions. Characterize the dirty PFer tests separately even though full PFer is later. | Inputs have hashes and licenses/provenance; independent expected numerical values, geometry and workbook semantics are recorded. The raw probe tests scientific bundling cheaply. The behaviour probe prevents falsely declaring the interface deep on the strength of one easy raw wrapper. Synthetic telemetry plots only test schema/renderer capability; they do not qualify telemetry calculations or source-data parity. This preserves behaviour-first full-product ordering.

Gate 0 validation should use real subprocesses and the actual host path where possible. Browser-only tests can validate React state but cannot replace installed-app launch, native grants, process-tree cleanup or offline qualification. Current Tauri documentation provides native testing options including an embedded WebDriver approach; choose and pin the mechanism and exclude test-only servers/plugins from production artifacts. [Tauri desktop tests](https://v2.tauri.app/develop/tests/webdriver/).

## Proposed measurable Gate 0 exit checklist

These initial bounds are proposals for a repeatable experiment. Record reference machine/OS/versions and p50/p95 where repeated; revise explicitly if measurements show a justified limit, rather than passing an undefined “acceptable” threshold.

- All three named target artifacts launch and complete G0-C/D/E offline with no system Python. A Windows run on a clean account without WebView2 demonstrates the selected offline prerequisite installation. macOS feasibility may use ad-hoc local signing; distribution signing/notarization remains a later hard gate.
- Protocol starts within 30 seconds cold; command acknowledgement within 250 ms after readiness; progress/liveness notification at least once per second while work continues. Indeterminate progress is allowed where no meaningful total exists.
- Maximum JSON frame 4 MiB; initial viewport at most 10,000 points per series and 50,000 across panels, with raw sample identity retained. A generated 1,000,000-sample trace produces its first bounded view within 5 seconds after data load, and cached pan/zoom requests within 250 ms p95 on the recorded reference machine. Full input loading/compute timings are recorded separately.
- Baseline working-set proposal: total host/sidecar/worker growth below 1 GiB for that synthetic trace; after ten load/close cycles, no retained session/job objects and no monotonic unbounded memory growth. Allow allocator caches in interpretation and record RSS, not only Python object size.
- Cancel acknowledgement within 250 ms after readiness; cooperative work reaches a terminal state within 2 seconds where checks exist. A blocked worker is stopped within a defined 10-second termination budget, preserving the control process and unrelated completed artifacts. If no safe bounded cancellation exists, Gate 0 fails rather than claiming stage-bound cancellation is instantaneous.
- Window close/host death terminates descendants within 10 seconds on each target. Sidecar restart invalidates old IDs. A completed result lost on restart is reported as lost unless a tested durable restoration feature exists.
- G0-C/D numerical and structural comparisons pass the explicitly recorded comparator, not a new ad hoc epsilon. Cross-target CSV text differences and workbook metadata differences are classified, never silently ignored. Plot geometry and source-value parity pass; cross-renderer pixel identity is not required.
- Fault injection before output publication, during staging, and at replacement/commit produces an unambiguous artifact manifest. Pre-existing files survive a cancelled/failed pre-commit job. Commit-phase failure recovery is demonstrated for the chosen single-workbook/PNG cut; full dual-PFer multi-file publication is a later required extension.
- All child import tests pass with PySide6 absent. Legacy app tests still have an independent runnable profile. Gate 0 reports what was executed, skipped or platform-blocked, with artifact hashes.

Do not expand Gate 0 into the full dashboard, complete settings migration, four-option raw UI, PFer workflow, complete behaviour modes, telemetry analysis, themes, recent files, updater, signing automation or retirement. Those remain required later where parity demands them. Do not freeze the final plot model until later feature cases have exercised it; version and extend it deliberately.

## Stop conditions and blocker ownership

Stop before full screen implementation if a target cannot package/run the scientific stack, the native transport cannot remain responsive while a worker runs, safe result/output ownership requires frontend orchestration, or the candidate renderer cannot represent the essential plot primitives. Report a measured alternative and revised scope rather than quietly dropping Intel macOS, exports or native-file behaviour.

Product/scientific owner: intended dirty baseline, known-defect policy, reachable versus optional library scope, numeric tolerances and supported datasets. Architecture owner: state/protocol/output contracts and renderer choice. Release owner: minimum OS, native test access, signing/distribution policy, installer identity/version and upgrade/rollback. Gate 0 can start with the stated defaults; final acceptance cannot substitute assumptions for missing target evidence.
